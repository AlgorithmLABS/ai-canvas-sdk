## OVERVIEW

Python 3.10+ SDK for AI Canvas custom nodes. Core surfaces are the public `ai_canvas_sdk` package, a local node-test CLI, protobuf/gRPC transport types, and Korean-language user docs.

## STRUCTURE

```text
|-- proto/                # source proto for generated gRPC code

|-- docs/                 # user-facing SDK docs and examples
|-- pyproject.toml        # packaging, deps, console script, setuptools-scm
`-- VERSIONING.md         # release and dev-tag policy
```

## CONVENTIONS

- Runtime imports assume package users can do `from ai_canvas_sdk import CustomNode, NodeSchema, NodeData, Port, ...`.
- Public node classes implement `get_schema()` and `run(inputs, parameters, ctx)`; `validate()` is mentioned in docs but is not abstract here.
- `pyproject.toml` owns dependencies and the `ai-canvas-sdk = "ai_canvas_sdk.cli:main"` console script, which resolves to `ai_canvas_sdk/cli/__init__.py`.
- Version source of truth is git tags through `setuptools-scm`; no static version in `pyproject.toml` or `__init__.py`.
- Korean docs/comments are normal in this repo. Preserve existing Korean user-facing copy when editing docs or CLI output.

## ANTI-PATTERNS

- Do not hand-edit `ai_canvas_sdk/grpc/custom_node_service_pb2.py`, `*_pb2_grpc.py`, or `*_pb2.pyi`; regenerate from `proto/custom_node_service.proto`.
- Do not add static package versions; releases and dev builds rely on `setuptools-scm`.
- Do not create incrementing `.devN` tags. `VERSIONING.md` documents why only `.dev0` anchors are used.
- Do not assume a test framework exists. No pytest/unittest config or test tree is present.
